Why it exists

Manifests are complete but noisy. README tech stacks are prose that rots.

package.json, pyproject.toml, Cargo.toml and friends are written for package managers. They include full trees, pinned versions, and dev tooling. Humans and agents need the label on the side of the box, not the supply chain.

AppFacts sits in between: curated, glanceable, and still machine-parseable via YAML frontmatter. YAML is the source of truth. The Markdown table is for humans. Schema validity does not prove the curated lines are complete or correct.

  • New contributors orienting in an unfamiliar repo
  • Future you, six months later
  • AI coding agents that need a fast structured read
  • Clients and stakeholders who want the stack without source

Extraction, curation, and verification

Three jobs. Do not collapse them into "the generator said so."

  • Extraction is deterministic. The scanner reads manifests, lockfile package-manager signals, framework and deploy files, README excerpts, a language census, and .env.example key names. It never reads source bodies or real .env files.
  • Curation is editorial. An LLM (or a human) selects stack lines, up to eight key dependencies, and optional services. Those lines need review. Absent evidence stays absent or unknown, not guessed.
  • Verification is separate. The schema checks required fields and enums. --check re-scans inputs and compares generated.inputs_fingerprint. Neither step proves the curated summary is true.

Autofill can copy repository from git remote, license from LICENSE* or the README, and package manager from the lockfile when those fields are blank. That is still extraction, not a review.

The format

Frontmatter you can validate. A table you can skim. Featured data is Smell Check, not the teaching snippet below.

---
app_facts_version: "0.1.0"
name: Acme Dashboard
type: web app (SPA)
status: active
license: MIT
stack:
  language: TypeScript
  framework: React 18 + Vite
  backend: Fastify
  database: PostgreSQL 16
key_dependencies:
  - name: zod
    purpose: Schema validation
services:
  - name: Stripe
    role: Billing
build:
  package_manager: pnpm
  test: Vitest + Playwright
generated:
  date: 2026-07-21
  generator: appfacts-cli v0.1.0
---

Spec document 0.1.2 — fields may still shift before 1.0. Files declare app_facts_version (0.1.0 today) so tooling can evolve with them.

Generate one

Smallest Node route: pass the project to scan, not the AppFacts checkout, unless you mean to label this repo. Node 18+, zero npm deps, local Ollama. 

# Scan /path/to/my-app (script location is not the target)
node /path/to/app-facts/generator/generate_app_facts.js \
  /path/to/my-app --provider ollama --model llama3.1

# Stale-input check, no model required
node /path/to/app-facts/generator/generate_app_facts.js \
  /path/to/my-app --check

# Python 3.8+
pip install -r /path/to/app-facts/generator/requirements.txt
python3 /path/to/app-facts/generator/generate_app_facts.py \
  /path/to/my-app --provider ollama --model llama3.1

Writes APP_FACTS.md and APP_FACTS.png. The QR opens a portable visual label at /v. Facts travel in the URL hash, with no server. Add --badge for a footer-ready HTML snippet (see get a badge).

Hosted providers (OpenAI, Anthropic, xAI, Gemini) are optional. There is no deterministic-only generate mode. --check is the no-model path, and it only compares scanned inputs to the stored fingerprint.

Optional credit footer: --consulting-link and --consulting-name.

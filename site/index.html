Why it exists

Manifests are complete but noisy. README tech stacks are prose that rots.

package.json, pyproject.toml, Cargo.toml and friends are written for package managers — full trees, pinned versions, dev tooling. Humans (and agents) need the label on the side of the box, not the supply chain.

AppFacts sits in between: curated, glanceable, and still machine-parseable via YAML frontmatter. YAML is the source of truth; the Markdown table is for humans.

  • New contributors orienting in an unfamiliar repo
  • Future you, six months later
  • AI coding agents that need a fast structured read
  • Clients and stakeholders who want the stack without source

The format

Frontmatter you can validate. A table you can skim.

---
app_facts_version: "0.1.0"
name: Acme Dashboard
type: web app (SPA)
status: active
license: MIT
stack:
  language: TypeScript
  framework: React 18 + Vite
  backend: Fastify
  database: PostgreSQL 16
key_dependencies:
  - name: zod
    purpose: Schema validation
build:
  package_manager: pnpm
  test: Vitest + Playwright
generated:
  date: 2026-07-21
  generator: appfacts-cli v0.1.0
---

Spec version 0.1 — fields may still shift before 1.0. Files declare app_facts_version so tooling can evolve with them.

Generate one

Dual generators (Python & Node) scan manifests and README — never your source — then ask an LLM to curate. Local-first via Ollama, or OpenAI / Anthropic / xAI / Gemini. 

# Node 18+ — zero npm deps
# Pass the project to scan (script location ≠ target):
node /path/to/app-facts/generator/generate_app_facts.js \
  /path/to/my-app --provider ollama --model llama3.1

# Python 3.8+
pip install -r /path/to/app-facts/generator/requirements.txt
python3 /path/to/app-facts/generator/generate_app_facts.py \
  /path/to/my-app --provider ollama --model llama3.1

Writes APP_FACTS.md and APP_FACTS.png. The QR opens a portable visual label at /v (facts travel in the URL hash — no server).
